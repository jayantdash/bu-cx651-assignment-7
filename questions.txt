(1) If a client-to-server message is dropped, the server will not process the move, and the client will keep waiting for a response. If a server-to-client message is dropped, the server may update the board, but the client will not receive the update and may remain waiting. Since UDP does not guarantee delivery and our implementation has no retry or timeout mechanism, the game may get stuck.
(2) If the server crashes while saving, the file may become corrupted or incomplete. If the file is missing, the game cannot be restored. Also, if a client restarts with a different port, the server may not recognize it. These issues can cause data loss or prevent the game from continuing.
